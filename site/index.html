Why rules first

1

Rules answer the obvious

A 50% test pass rate does not need a model to call it risky. A rule says so in microseconds with a reason an auditor can read.

2

The model sees the rest

The same rules filter the training data, so the model learns only the cases it will actually receive. Training on rule-solved rows would teach it a shortcut it never gets to use.

3

Built to map to SageMaker

The repo includes a training entry point for the SageMaker contract, a Terraform file, and notes on monitoring, rollback, security and cost. None of it was run against AWS.

Train and serve it locally

Python 3.12. No AWS credentials needed.

python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pip install -e .

python -m release_risk_ml.training.generate_data --n-rows 5000 --seed 42
python -m release_risk_ml.training.train --data data/releases.csv --model-dir artifacts
uvicorn release_risk_ml.serving.app:app --port 8000
scripts/smoke_test.sh http://localhost:8000

python -m pytest tests/ -v

The README lists the held-out metrics from its own training run on the synthetic data. They are modest by design, since the rules already removed the easy rows.

What this does not do
  • The author has no prior production SageMaker experience, and the README says so. This was not deployed on AWS.
  • All data is synthetic, generated from a hand-written risk function. Nothing here predicts real deploys.
  • This page runs the rules, the data generator and the drift check. It does not train or run the model.
  • The monitoring functions are tested against synthetic batches, not wired to live traffic.
